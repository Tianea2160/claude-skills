# 예시

## 작업 분해 예시

Phase 2.1에서 TaskCreate로 태스크를 세분화할 때 참고한다.

```
Task 1: [선행 없음] 도메인 모델 정의
Task 2: [Task 1 의존] Repository 구현
Task 3: [Task 2 의존] Service 로직 구현
Task 4: [Task 1 의존] API 엔드포인트 작성
Task 5: [Task 3, 4 의존] 통합 테스트
```

각 태스크는:
- 독립적으로 완료 가능한 단위
- 의존성이 명확 (선행 작업 명시)
- 검증 가능 (완료 조건 명시)

---

## 병렬 실행 예시

Phase 2.2에서 수정 파일이 겹치지 않는 태스크를 병렬로 실행할 때 참고한다.

```
Task 1: 도메인 모델 정의 → 완료 후
  ├─ Task 2: Repository 구현 (Agent A) ──┐ 파일이 겹치지 않으므로 병렬
  ├─ Task 4: API 엔드포인트 작성 (Agent B) ─┘
  └─ 둘 다 완료 후 → Task 3, Task 5 순차 진행
```

병렬 실행 판단 기준:
- 각 태스크가 수정/생성하는 파일 목록이 서로 겹치지 않을 것
- 병렬 실행 시 각 Agent에게 태스크의 목적, 수정할 파일, 준수할 패턴을 명확히 전달
