# 템플릿

## 구현 계획 작성 가이드

Phase 1.4에서 EnterPlanMode 진입 후, 아래 구조에 따라 **구체적인 구현 계획**을 작성한다.
작성 완료 후 ExitPlanMode로 사용자 승인을 요청한다.

```
## 목표

[무엇을 왜 만드는가 — 1~2문장으로 요약]

## 구현 전략

[접근 방식과 선택 근거. 대안이 있다면 왜 이 방식을 택했는지]

## 변경 계획

| 파일 | 변경 유형 | 구체적 내용 |
|------|---------|------------|
| `path/file.ts` | 수정 | 함수 X를 Y로 변경하여 Z 지원 |
| `path/new.ts` | 생성 | 역할: ... |

## 재사용할 기존 코드

- `file:line` — [무엇을, 어떻게 활용하는지]

## 작업 순서

### 1. [태스크 제목 — TaskCreate의 subject로 사용]
- **내용**: [구체적 할 일 — TaskCreate의 description으로 사용]
- **의존**: 없음

### 2. [태스크 제목]
- **내용**: [구체적 할 일]
- **의존**: 1번 완료 필요

### 3. [태스크 제목]
- **내용**: [구체적 할 일]
- **의존**: 없음 (2번과 병렬 가능)

## 외부 참고사항

- [조사에서 발견한 best practice, 주의점]
```

**작성 원칙:**
- 변경 계획은 **파일 단위**로 구체적으로 기술한다 (무엇을 어떻게 바꾸는지)
- 작업 순서의 각 항목은 **제목 → TaskCreate의 subject**, **내용 → description**으로 직접 매핑되게 작성한다
- 모호한 표현("개선한다", "정리한다")을 피하고 **구체적 행위**를 기술한다

---

## 작업 완료 보고 — 마크다운 렌더링 가이드

Phase 4의 **사용자 노출 단계**는 모델 텍스트로 직접 출력한다.
Bash 도구의 출력은 Claude Code UI에서 요약·축소되어 보이지 않을 수 있으므로
마크다운 서식과 유니코드 심볼로 시각 계층을 표현한다.

**중요:** 정보 구성(무엇을 보고할지 결정하는 단계)은 기존대로 모델 내부에서 수행한다.
마크다운 출력은 **최종 노출 순간 한 번만** 사용한다.

### 심볼 팔레트 (의미 고정)

| 표현 | 용도 |
|------|------|
| `✓` | 성공, 완료, 충족 |
| `⚠` | 경고, 부분 완료 |
| `✗` | 실패, 블로커 |
| `**▸ 섹션명**` | 섹션 헤더 (볼드+심볼 조합) |
| `**볼드**` | 키워드 강조 |
| `` `$ 명령어` `` | 실행 명령어 |

### 볼드 선정 규칙

볼드만 읽어도 리포트의 뼈대가 전달되도록 구성한다:

1. **동사구 앞의 핵심 명사** — "알림 핸들러 **신규**", "설정 **수정**"
2. **고유 식별자** — 함수명, 클래스명, 설정 키 (긴 경로는 제외)
3. **수치** — "4/4", "2건", "7일"
4. **상태어** — "통과", "충족", "실패", "블로커"
5. **후속 작업의 행위 대상** — "**Redis 클러스터** 설정"

### 마크다운 렌더링 패턴

아래 패턴을 현재 작업 내용으로 채워 모델 텍스트로 출력한다:

```
──────────────────────────────────────────
  ✓ 기능 구현 완료   **<기능명>**
──────────────────────────────────────────

<TL;DR 한두 줄, 핵심 명사구는 **볼드**>

**▸ 핵심 변경**
  - **<변경 1 요지>** — <부연 설명>
  - **<변경 2 요지>** — <부연 설명>

**▸ 검증 결과**
  ✓ 요구사항 **<n/n 충족>**
  ✓ 코드 품질 **통과**
  ⚠ 경고 **<n건 수정 완료>**

**▸ 후속 작업**
  - **<대상>** <부연>

**▸ 테스트 방법**
  `$ <명령어>`
──────────────────────────────────────────
```

### 상태별 변형

- **완료**: `✓ 기능 구현 완료` — 기본
- **부분 완료**: `⚠ 부분 완료` — TL;DR에 미완료 사유 먼저 기술
- **실패/블로커**: `✗ 구현 중단` — **블로커 섹션을 검증 결과보다 앞**에 배치
- **경고만 있음**: `✓ 기능 구현 완료` 유지 — 검증 결과 섹션에 ⚠ 심볼로 표시

### 금지 사항

- 파일 경로 전체 나열 금지 — 사용자는 의미 단위 요약을 원한다
- 박스 테두리(`│ ╭ ╮`) 금지 — CJK 폭 문제로 정렬 깨짐
- Bash 도구로 보고서 출력 금지 — UI에서 요약·축소되어 보이지 않고, 마크다운 서식이 Bash stdout에서 렌더링되지 않음
