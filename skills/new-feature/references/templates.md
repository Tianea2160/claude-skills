# 템플릿

## 구현 계획 작성 가이드

Phase 1.4에서 EnterPlanMode 진입 후, 아래 구조에 따라 **구체적인 구현 계획**을 작성한다.
작성 완료 후 ExitPlanMode로 사용자 승인을 요청한다.

```
## 목표

[무엇을 왜 만드는가 — 1~2문장으로 요약]

## 구현 전략

[접근 방식과 선택 근거. 대안이 있다면 왜 이 방식을 택했는지]

## 변경 계획

| 파일 | 변경 유형 | 구체적 내용 |
|------|---------|------------|
| `path/file.ts` | 수정 | 함수 X를 Y로 변경하여 Z 지원 |
| `path/new.ts` | 생성 | 역할: ... |

## 재사용할 기존 코드

- `file:line` — [무엇을, 어떻게 활용하는지]

## 작업 순서

### 1. [태스크 제목 — TaskCreate의 subject로 사용]
- **내용**: [구체적 할 일 — TaskCreate의 description으로 사용]
- **의존**: 없음

### 2. [태스크 제목]
- **내용**: [구체적 할 일]
- **의존**: 1번 완료 필요

### 3. [태스크 제목]
- **내용**: [구체적 할 일]
- **의존**: 없음 (2번과 병렬 가능)

## 외부 참고사항

- [조사에서 발견한 best practice, 주의점]
```

**작성 원칙:**
- 변경 계획은 **파일 단위**로 구체적으로 기술한다 (무엇을 어떻게 바꾸는지)
- 작업 순서의 각 항목은 **제목 → TaskCreate의 subject**, **내용 → description**으로 직접 매핑되게 작성한다
- 모호한 표현("개선한다", "정리한다")을 피하고 **구체적 행위**를 기술한다

## 작업 완료 보고 — 터미널 렌더링 가이드

Phase 4의 **사용자 노출 단계**는 Bash `printf`로 출력한다.
Claude Code는 모델 텍스트 출력의 ANSI escape를 무력화하므로
Bash tool의 stdout 경로만 색상이 렌더링된다.

**중요:** 정보 구성(무엇을 보고할지 결정하는 단계)은 기존대로 모델 내부에서 수행한다.
Bash printf는 **최종 노출 순간 한 번만** 사용한다.

### 구조

1. **상단 구분선**
2. **상태 뱃지 + 기능명** (`✓ 기능 구현 완료   <기능명>`)
3. **하단 구분선**
4. **TL;DR** — 1~2줄 핵심 요약 (구분선 바깥)
5. **▸ 핵심 변경** — 파일 나열이 아니라 **의미 단위** 3~5개
6. **▸ 검증 결과** — 요구사항 충족, 품질, 경고 건수
7. **▸ 후속 작업** — 운영 환경 설정, 후속 스프린트 등
8. **▸ 테스트 방법** — 명령어, 엔드포인트
9. **하단 구분선**

### 색상 팔레트 (의미 고정)

| 변수 | ANSI | 용도 |
|------|------|------|
| `C` | `\033[1;36m` | bold cyan — 구분선, 섹션 헤더 |
| `G` | `\033[1;32m` | bold green — 성공, 완료, 충족 |
| `Y` | `\033[1;33m` | bold yellow — 경고, 부분 완료 |
| `R` | `\033[1;31m` | bold red — 실패, 블로커 |
| `B` | `\033[1m` | bold — 키워드 강조 |
| `D` | `\033[2m` | dim — 명령어, 부가 정보 |
| `X` | `\033[0m` | reset |

### 볼드 선정 규칙

볼드만 읽어도 리포트의 뼈대가 전달되도록 구성한다:

1. **동사구 앞의 핵심 명사** — "알림 핸들러 **신규**", "설정 **수정**"
2. **고유 식별자** — 함수명, 클래스명, 설정 키 (긴 경로는 제외)
3. **수치** — "4/4", "2건", "7일"
4. **상태어** — "통과", "충족", "실패", "블로커"
5. **후속 작업의 행위 대상** — "**Redis 클러스터** 설정"

### Bash 렌더링 패턴

아래 패턴을 현재 작업 내용으로 채워 Bash 도구로 실행한다:

```bash
C='\033[1;36m'; G='\033[1;32m'; Y='\033[1;33m'; R='\033[1;31m'
B='\033[1m'; D='\033[2m'; X='\033[0m'

printf "${C}──────────────────────────────────────────${X}\n"
printf "  ${G}✓ 기능 구현 완료${X}   ${B}<기능명>${X}\n"
printf "${C}──────────────────────────────────────────${X}\n\n"

printf "<TL;DR 한두 줄, 핵심 명사구는 ${B}...${X}로 감쌈>\n\n"

printf "${C}▸ 핵심 변경${X}\n"
printf "  • ${B}<변경 1 요지>${X} — <부연 설명>\n"
printf "  • ${B}<변경 2 요지>${X} — <부연 설명>\n\n"

printf "${C}▸ 검증 결과${X}\n"
printf "  ${G}✓${X} 요구사항 ${B}<n/n 충족>${X}\n"
printf "  ${G}✓${X} 코드 품질 ${B}통과${X}\n"
printf "  ${Y}⚠${X} 경고 ${B}<n건 수정 완료>${X}\n\n"

printf "${C}▸ 후속 작업${X}\n"
printf "  • ${B}<대상>${X} <부연>\n\n"

printf "${C}▸ 테스트 방법${X}\n"
printf "  ${D}\$ <명령어>${X}\n"
printf "${C}──────────────────────────────────────────${X}\n"
```

### 상태별 변형

- **완료**: `${G}✓ 기능 구현 완료${X}` — 기본
- **부분 완료**: `${Y}⚠ 부분 완료${X}` — TL;DR에 미완료 사유 먼저 기술
- **실패/블로커**: `${R}✗ 구현 중단${X}` — **블로커 섹션을 검증 결과보다 앞**에 배치
- **경고만 있음**: `${G}✓ 기능 구현 완료${X}` 유지 — 검증 결과 섹션에 yellow로 표시

### 금지 사항

- 파일 경로 전체 나열 금지 — 사용자는 의미 단위 요약을 원한다
- 배경 반전(inverted) 금지 — 단순 컬러 텍스트만
- 박스 테두리(`│ ╭ ╮`) 금지 — CJK 폭 문제로 정렬 깨짐
- 무지개 색상 금지 — 팔레트 6색 외 사용 금지
